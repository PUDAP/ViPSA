# Explicit continuation after weak-contact or failed retention gates

For a multi-device physical optimization campaign, distinguish **measurement validity** from **hardware safety**. If the user explicitly says not to stop testing because prior sites had weak/ambiguous contact, continue bounded exploratory measurements on subsequent sites. Record invalid contact/retention as a quality flag, not a campaign-wide halt. Never relax output-off, matrix-open/nil, safe XY travel clearance, stress compliance, read-compliance, or energy guards; a true hardware fault still stops and triggers cleanup.

Compare multiple bounded recipes sequentially on the **same** device with fixed low-bias read voltage, settle/read count and delayed-read interval. Keep the order, cumulative stress, measured point timestamps, read-clamp and energy flags. A forming/compliance event is not a valid ON state. A ratio computed from offset-dominated or wrong-direction reads is `apparent_unqualified`, not an optimized ON/OFF ratio. Repeat the best-looking recipe *exactly* on that device with interleaved baseline controls, then reproduce on another device before starting endurance. Continue to the next candidate if quality remains poor but hardware is safe.

Demonstrated pitfall: one sequential recipe generated an apparent delayed SET/post-RESET ratio above 100, but two exact repeats on that same site returned ratios below one because delayed SET current relaxed to the offset floor. The single maximum was an exploratory outlier, not a recipe optimum. Plot the measured points only when connecting compliance-limited sweeps would visually imply unsampled transitions; preserve raw ordered CSV/JSON and editable SVG in all cases.
