# Historical recipe repeat after accepted partial preparation

## When to use
An optimizer hands a historical batch to a hardware executor on a newly identified substrate, but the current device has already received forming under a preceding manual request.

## Procedure
1. Resolve ambiguous date/round labels using original manifest plus execution timestamps. Do not silently combine one round's recipe with another round's protocol.
2. Hash-check manifest and every recipe source/copy, enumerate the complete fresh bindings, and treat historical absolute coordinates and run IDs as provenance only. Capture the live grid origin and verify signed axis directions before travel.
3. Audit actual saved command envelopes, not only the six optimizer parameters or abstract intention metadata. Compare all ordered voltages, continuous segment order, compliance, range, NPLC, dwell, reset/ADR settings, health commands, cycle cap and consecutive-failure definition. An intention's acquisition-window metadata need not be present in the actual dispatched command; report what was actually executed.
4. Preserve an append-only correction if the operator identifies the current device as belonging to a new substrate. Link prior native data to that corrected device; neither erase exposure nor carry the previous device number forward.
5. If the user explicitly accepts the forming difference and says continue from conditioning, record the exception and execute the first missing conditioning operation. Do not replay forming, add a historical post-forming motion, or re-ask the resolved decision. Acceptance does not waive separate energy limits, unknown-exposure stops or cycle caps.
6. Carry actual prior-stress counts into the original preparation-health cadence. For an every-tenth-stress schedule with eight prior forming sweeps, health is due after preparation sweeps 2 and 12. Do not reset this counter at the handoff or confuse it with the candidate full-cycle counter.
7. Acquire the sole owner; verify current OFF/open/errors/pose/deployment before stress. Journal fresh identities and durable INTENT/native-receipt/COMPLETE records. Stop on unknown exposure; never replay automatically. Keep cleanup verified at terminal boundaries.
8. Report received, validated, started and verified-complete distinctly. A delayed failure of a superseded zero-stress launcher is not proof that the replacement worker failed. Read its exact journal.

## Verified example and limits
An eight-recipe historical handoff was checked against the Oct-14 round-2 D51 records. Thirteen preparation command payloads, twenty continuous-batch segments and health settings matched exactly. Fresh device1 already had eight +10V forming sweeps rather than historical +8V preparation; the operator accepted this and requested conditioning onward. The replacement worker verified the first negative preparation sweep and first positive conditioning SET, then reached the due health-read operation. This checkpoint does not establish completed conditioning, endurance, or success of subsequent devices.

Do not turn this example's voltages, grid pitch, counts or coordinates into defaults for other campaigns. Reconstruct them from the selected source and current authorization.
